# 상품 성별·이미지 품질 교정 (2026-09-26)

## 확인된 원인과 방어 규칙

- 일부 공식몰의 상품 대상 표기보다 목록 카테고리 성별을 우선해 오분류했다. `(woman)`, `FOR MEN` 같은 명시적 상품명과 검증된 DRAE/MONDAY EDITION 표기를 우선하되, 반대 URL 근거와 충돌하면 미확인으로 남긴다. 일반 스타일명은 새로운 대상 표기로 취급하지 않는다.
- 구조화 데이터에 이미지가 하나라도 있으면 상세 갤러리 수집을 끝내던 경로를 제거했다. 현재 상품의 구조화 데이터와 상세·갤러리 DOM을 함께 수집한다.
- 페이지 전체 이미지 탐색으로 추천상품, 공통 캠페인, 옵션 썸네일이 섞였다. 상세 영역의 상위 요소와 상품 링크를 확인하고 추천·배너·내비게이션·스와치·placeholder를 제외한다.
- 모델 사진의 시각적 점수만으로 대표 이미지를 교체하지 않는다. 기본 선택은 공식 원본 및 수집 순서를 보존하고, 명시적으로 검증한 이미지 집합을 전달한 경우에만 시각적 순위를 적용한다.

상품 소유권 검증은 DOM/URL/메타데이터 근거에 대한 검증이다. 사진 내용이 실제 동일 상품인지 의미적으로 판정하는 모델 검증은 아니므로, 공식몰 자체의 잘못된 사진이나 모호한 페이지는 별도 검토가 필요하다.

## PR 전 추가 예외 검증

- 동일 Cafe24 상품번호라도 다른 variant는 별도 상품으로 취급한다. 다른 포트·비웹 스킴·쿼리형 다른 상품 링크도 제외한다.
- 추천상품 JSON-LD, 잘못된 OG URL, 주석·스크립트·템플릿 속 가짜 메타데이터를 현재 상품 근거로 사용하지 않는다.
- 따옴표·`>`가 포함된 속성, boolean 옵션 속성, 빈 `srcset`과 lazy `data-srcset`, 브라우저 컴포넌트 갤러리를 처리한다.
- `FOR MEN AND WOMEN`처럼 혼합된 대상 표기는 사이트별 남성 규칙이 있어도 기존 단일 성별을 강제 반전시키지 않는다.
- 읽기 전용 교정 계획 도구는 빈/잘못된 ID 범위, 스냅샷에 없는 ID, 중복 스냅샷 ID, 경로형 ID를 파일/네트워크 작업 전에 거부한다.

수집 버전은 `product-images-v4-scoped`, 선택 버전은 `mac-vision-v5-owned-gallery` / `win-cv-v3-owned-gallery`다. 이전 버전으로 표시된 풀은 현재 검증을 통과한 풀로 간주하지 않는다.

## 검증 결과

- `pnpm typecheck`: 통과.
- `pnpm test`: 919개 통과, 실패·skip 없음.
- 이전 교정 과정에서 저장한 실제 상품 HTML 4,411개를 이전 배포본과 비교: 전체 이미지 목록 동일, 추가·삭제·빈 풀 전환 0건. 이 결과는 저장한 페이지에 대한 회귀 확인이며 모든 쇼핑몰 템플릿을 보장하지 않는다.
- 회귀 테스트 및 저장된 페이지 재생에는 운영 DB 쓰기, 실크롤링, 외부 AI API를 사용하지 않았다.

## 이전 운영 교정 결과와 남은 범위

이전 승인된 작업에서 고유 상품 4,445개를 교정했다: 성별 184개, 단일 이미지 풀 보강 3,944개, 대표 이미지/갤러리 오염 교정 317개. 대표 이미지가 바뀐 317개는 품절 상품을 포함해 로컬 FashionSigLIP으로 재임베딩했고 당시 URL/revision 일치와 미완료 0건을 확인했다.

공식 페이지 404 또는 상품명 불일치로 이미지 후보 78개, 모호한 근거나 미등록 사이트로 성별 후보 22개는 자동 교정하지 않았다. 실제 이미지가 하나뿐인 3개도 그대로 보존했다. 404 상품 중 별도로 검증해 복원한 16개의 대표 이미지는 확인됐지만 전체 갤러리까지 복구됐다는 뜻은 아니다.

기존 v3 수정은 앞선 승인으로 연구실에 배포됐다. **이 PR에서 추가한 v4 예외 보강은 아직 재배포하지 않았다.** PR 작성 과정에서 운영 데이터도 추가 변경하지 않았다.

## 읽기 전용 교정 계획 도구

```bash
pnpm exec tsx tools/plan-product-quality-repair.ts \
  --snapshot=/secure/audit-snapshot.json \
  --out=/secure/review/plan.jsonl \
  --ids=123,456 --concurrency=4
```

입력의 `rows`는 도구의 `AuditRow` 계약을 따른다. ID는 양의 bigint 십진 문자열이어야 한다. `--ids` 생략 시 입력 스냅샷 전체만 검토하며, 빈 `--ids=`는 오류다. 출력은 기존 파일을 덮어쓰지 않는다. 공식 호스트·robots·상품 ID·상품명 확인을 거친 계획과 근거만 저장하고 DB에는 연결하지 않는다. 네트워크 요청은 발생하므로 실행 전 대상 범위를 확인한다.

계획을 실제 적용하려면 별도 승인, 원본 백업, 행별 기존값 비교, 이미지 변경에 따른 embedding 무효화/재생성 절차가 필요하다. 이 도구에는 DB 적용 기능이 없다. 운영 스냅샷·백업 벡터·수집 HTML은 저장소에 커밋하지 않는다.
